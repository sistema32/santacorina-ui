Instalación

Cómo sumar @sistema32/santacorina-ui a un sistema nuevo, con o sin Node, y cómo conectar sus utilidades JS. Requiere tailwindcss@^4.0.0 como peer dependency si usas el modo "con tu build de Tailwind" — el modo "sin Node" no lo necesita en absoluto.

1. Instalar el paquete

Un solo paquete trae el CSS (plugin de Tailwind) y el JS — se consumen por separado según lo que necesite el sistema.

npm install @sistema32/santacorina-ui

2. Con tu propio build de Tailwind

El caso normal para un sistema con Node y Vite/Webpack ya corriendo Tailwind v4. Agrega el @plugin en el CSS de entrada:

/* src/estilos.css */
@import "tailwindcss";
@plugin "@sistema32/santacorina-ui";

Eso agrega los ~16 colores de marca como utilidades (bg-navy, text-azul-oscuro, border-rojo-fondo…) y los componentes (.tarjeta, .kpi, .etiqueta, .boton, .campo, etc.) disponibles en cualquier plantilla que Tailwind ya esté escaneando — sin copiar CSS entre repos.

3. Sin Node (backend sin build propio)

El caso real de sgp: el backend Python no tiene Node en su imagen de producción. dist/ui.css es el plugin ya compilado contra Tailwind — se enlaza directo, sin paso de build ni Tailwind instalado del lado del consumidor.

<link rel="stylesheet" href="node_modules/@sistema32/santacorina-ui/dist/ui.css">

4. Utilidades JS

Dos modos de consumo, mismo criterio que el CSS: uno con auto-arranque para plantillas sin bundler, otro explícito para quien ya tiene su propio ciclo de vida (Vue y similares).

<!-- sin bundler (plantillas Jinja) -->
<script src="node_modules/@sistema32/santacorina-ui/dist/js.global.js"></script>
<!-- expone window.Santacorina y ya auto-arrancó .lateral-toggle, .tabs, etc. -->
// con bundler (Vue u otro) -- esta entrada NO se auto-ejecuta
import { formato, mostrarToast, abrirModal, iniciarTodo, destruirTodo } from "@sistema32/santacorina-ui/js";

// onMounted(() => iniciarTodo(raizRef.value));
// onUnmounted(() => destruirTodo(raizRef.value));

El listado completo de funciones (qué hace cada una y si se auto-inicia) está en JS / Utilidades.

5. Personalizar colores y tipografía

Los tokens de marca son variables CSS en un :root sin @layer — eso le gana a cualquier regla dentro de un layer (el plugin define sus colores en @layer base) sin importar el orden en que aparezcan en el archivo.

@import "tailwindcss";
@plugin "@sistema32/santacorina-ui";

:root {
  --color-azul: #1d4ed8;
  --font-sans: 'Inter', sans-serif;
}

--font-sans es el mismo nombre que usa el tema por defecto de Tailwind v4 para font-sans — el override también alcanza esa utilidad y el <html> base, no solo body. Sin fuente propia, el navegador cae a system-ui (el paquete no carga ningún <link> de Google Fonts por su cuenta). Más detalle en Fundamentos → Tipografía.

6. Modo oscuro

Sigue prefers-color-scheme por defecto. data-theme="dark"/"light" en cualquier ancestro (típicamente <html>) lo fuerza a mano — mismo mecanismo que colores y tipografía, solo variables CSS.

<!-- forzar oscuro sin importar el sistema operativo -->
<html data-theme="dark">
