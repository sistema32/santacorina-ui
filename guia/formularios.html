Formularios

Campos, grupos, validación y los patrones de accesibilidad de GOV.UK Design System para formularios largos.

Campo

Un control de formulario con su etiqueta y texto de ayuda.

Se usa para vincular la solicitud al presupuesto correcto.

<div class="campo"><label>RBD</label><input type="text"></div>

Error de campo

Complementa .resumen-errores (ya existente): el resumen enlaza al campo, esto muestra por qué, junto al control. [aria-invalid="true"] funciona en cualquier input/select/textarea sin una clase nueva.

El RUT ingresado no es válido.

<input aria-invalid="true" aria-describedby="x-error"><p class="campo-error" id="x-error"><span class="icono icono-advertencia"></span>El RUT...</p>

Checkbox / radio

Nativos, solo con accent-color de marca — no un input oculto + div decorado.

<div class="campo-check"><input type="checkbox" id="c1"><label for="c1">Recepción conforme</label></div>

Interruptor

On/off — activar o desactivar algo (ej. un destino de Finanzas).

<label class="interruptor"><input type="checkbox"><span class="pista"></span></label>

Rango

Mismos colores que .barra-progreso.

<input type="range" min="0" max="100" value="65">

Archivo

Marca solo sobre el botón "Elegir archivo" — el cuadro de diálogo del sistema operativo no se toca.

<input type="file">

Buscador

input[type=search] ya trae un botón nativo de limpiar, pero depende del navegador y no tiene ícono — se oculta y se reemplaza por uno de marca (iniciarBuscadores).

<div class="buscador"><input type="search"><button class="limpiar">×</button></div>

Contador de caracteres

Sobre un textarea con maxlength — marca .cerca al 90% y .lleno al límite (iniciarContadores).

0/120 
<textarea data-contador maxlength="120"></textarea><span class="contador-caracteres"></span>

Grupo de campo

Prefijo/sufijo pegado a un input — esta plataforma maneja montos en pesos en cada tabla.

$ 
<div class="grupo-campo"><span class="prefijo">$</span><input type="text"></div>

Fieldset / leyenda

El HTML nativo correcto para agrupar varios .campo-check bajo una sola pregunta — antes solo existía el estilo del ítem individual.

Tipo de solicitud 
<fieldset class="campo-grupo"><legend>Tipo de solicitud</legend><div class="campo-check">...</div></fieldset>

Combobox

Select con autocompletado sobre un <select> oculto — sigue funcionando con un form normal si el JS falla. Filtra sin distinguir tildes.

    <div class="combobox"><input type="text"><select>...</select><ul class="combobox-opciones"></ul></div>

    Medidor de contraseña

    Heurística simple (longitud + variedad de caracteres) para una guía visual — la seguridad real la sigue validando el backend.

    <input type="password" data-medidor-clave>

    Agrupa los .campo de un formulario largo bajo un título, en vez de dejarlos todos sueltos uno tras otro.

    <div class="formulario-seccion"><h4 class="formulario-seccion-titulo">...</h4><div class="campo">...</div></div>

    Resumen de revisión

    De GOV.UK "summary list" — pares clave/valor con acción "Cambiar", para la pantalla de revisión antes de enviar (cierra el flujo de .asistente/.paso). Solo CSS.

    EstablecimientoEscuela Básica N°1Cambiar
    Monto solicitado$1.422.169Cambiar
    <div class="resumen-revision-item"><span>Establecimiento</span><strong>Escuela Básica N°1</strong><a class="cambiar">Cambiar</a></div>

    Resumen de errores

    De GOV.UK "error summary" — el patrón de accesibilidad de formularios mejor documentado que encontré. iniciarResumenErrores enfoca la caja apenas aparece y mueve el foco al campo destino al hacer clic en un link.

    Hay 2 problemas con tu formulario

    • El RUT ingresado no es válido
    • El monto debe ser mayor a 0
    <div class="resumen-errores"><h2>Hay 2 problemas...</h2><ul><li><a href="#campo-rut">El RUT...</a></li></ul></div>

    Validación con guardado

    iniciarFormularios conecta la Constraint Validation API nativa del navegador (checkValidity()) a .campo-error/.resumen-errores de arriba en cada <form data-validar>: envía el form vacío y mira. Reglas entre campos (ej. confirmar contraseña) siguen siendo del consumidor vía input.setCustomValidity(...) nativo — el paquete no inventa un motor de reglas. ponerCargando/quitarCargando ponen el botón en "Guardando…" sin cambiar su ancho (el texto real sigue ahí, oculto con color:transparent) y evitan un doble envío.

    <form data-validar>
  <input required data-mensaje-error="Ingresa un RUT válido">
  <button type="submit">Guardar</button>
</form>
<script>
  form.addEventListener("submit", function (e) {
    if (e.defaultPrevented) return; // iniciarFormularios ya marco los errores
    Santacorina.ponerCargando(boton);
    fetch(...).then(() => ...).catch(() => Santacorina.quitarCargando(boton));
  });
</script>
